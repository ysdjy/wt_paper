## 追加修复（用户报告后发现的真实问题）

用户反馈："D1、D2、D3 和 (a) 的标题靠图太近了，还有 (a) 图和下面的三个图离得太远了，中间留白
很多。"打开 PNG 核实，两个问题都真实存在，且根因和我最初的假设相反：

1. **D1/D2/D3 与 (a) 标题太挤**：`panel_a_task()` 里 D1/D2/D3 子标题的偏移量原来是
   `y=-0.10`（离热力图很近），"(a)" 组标题又紧跟其后（只有 `-0.010` 的间距）。已分别放宽到
   `y=-0.16` 和 `-0.026`，三层文字现在有清楚的呼吸空间。

2. **(a) 与 (b)/(c) 之间留白过大**：根因是 **`hspace` 而不是 spacer 行**。在这个 3 行
   GridSpec 里，`hspace` 是按"所有行高度的平均值"计算的，同时作用在 row0↔spacer 和
   spacer↔row2 两处间隙上；`hspace=0.55` 在这里实际产生了约 0.79 个高度单位的额外间隙——
   比行本身的高度（1.05/1.0）还要接近，比显式 spacer（当时只有 0.10）大得多。上一轮"只调小
   spacer、不动 hspace"的假设用错了地方：在 Fig4-2 那次，`hspace` 确实不是主因；但在 Fig4-3
   这个只有 3 行、spacer 很薄的结构里，`hspace` 才是真正的主因。

   修复：把 `hspace` 从 `0.55` 降到 `0.32`（中间尝试过 `0.15`，导致 row2 整体上移撞进
   (a) 的图例/标题，已打开 PNG 发现并回退到更合适的中间值），显式 spacer 从 `0.10` 恢复到
   正常的 `0.14`，让 spacer 重新承担"可控的、有意为之的间隙"这个角色，而不是被 hspace
   的隐藏叠加效应主导。整图高度顺带从 132mm 降到 128mm。
